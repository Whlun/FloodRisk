# 生态整治管理平台

## 📋 业务与功能

### 1.1 核心目标

生态整治管理平台是为水环境治理工作打造的综合管理信息系统，整合**项目管理**与**河湖长制**两大核心业务模块，实现生态治理项目全生命周期管理与河湖管护责任体系数字化。平台旨在提升水环境治理工作的信息化水平，为管理部门提供决策支持，为基层人员提供工作便利，为公众提供监督渠道。

### 1.2 功能清单

| 信息展示 | P0 | 展示项目名称、编号、类型、建设地点、规划工期、投资金额、责任单位、施工单位等核心信息 |

### 1.3 交互要点

- **模块切换**：左侧一级分组「项目管理」「河湖长制」可展开/收起，点击子项进入对应页面（对齐「韶山水环境设施管理系统」侧栏交互）
- **功能导航**：子菜单项展示各功能页面；面包屑为主区首行 `breadcrumb-bar` 文案
- **数据列表**：表格展示+搜索筛选+分页；列表操作列与设施管理一致为「**详情**」「**编辑**」（`action-btn detail` / `action-btn edit` 配色）；**删除**仅在对应记录的**编辑弹窗**底部（危险按钮 + 二次确认），不在表格行内
- **详情查看**：点击列表项进入详情页或抽屉展示完整信息
- **地图展示**：责任段在详情/编辑中展示起点—讫点 **示意地图**（见责任段信息）；项目成果等可扩展地图可视化
- **责任段详情弹窗信息布局**：字段与地图统一放入**单一 `Descriptions` 描述列表**连续展示，不拆分多段描述块

### 2.2 数据来源

- **数据类型**：列表数据、表单数据、统计数据、地理数据
- **数据源**：生成示例数据（本原型阶段）
- **河湖长制建表规范**：参照 **DB4401/T 138—2021《河（湖）长制管理信息系统数据规范》**（广州市地方标准，数据库建设字段与表名以该标准为准）。原型实现见 `riverChiefDb4401.ts`，主要对应关系：
  - **实体关系（原型落地）**：**河流（涌）对象 1:N 责任段**（责任段 `linkedRiverObjectId` →河流主数据 `riverObjectId`）；**段与段衔接**仍由表9类字段 `PARENT_ID` 表达；**湖泊（水库）与河流/河段连通**用 `connectedRiverObjectId`、`connectedSectionId` 及说明文字表达（对接时以标准/地方扩展表字段为准）
  - **FOU_RIVER** 河流（涌）信息表：河段编码 `SECTION_ID`（26 位分段码）、`SECTION_NAME`、`RIVER_SYSTEM`、`RIVER_SIDE`（L/R/A）、`SENCTION_TYPE`（1–4）、`ADDVCD`、`ADMIN_LEVEL`（A–E）、河段长度与汇水面积等
  - **FOU_RIVER_INFO_DOC** 表9「一河一档」河流（段）自然属性：`PARENT_NAME`/`PARENT_ID`、`START_LGTD`/`START_LTTD`、`END_LGTD`/`END_LTTD`、`RIVER_LEN`、`RIVER_DIST`（L/R/T/E）、`AREA`、`RUNOFF_VOLUME`、`LOWFLOW_VOLUME`、`GAUGING_STATION`、`LEFT_BRANCH`、`RIGHT_BRANCH` 等（原型合并于责任段一条记录）
  - **DYN_PATROL** 巡河记录表：台账头 `PATROL_ID`、`SECTION_ID`、`USER_ID` 等；**一条巡检信息**对应 **多条巡检记录**（`PatrolRecordRow.segments[]`）：**本段巡检人员** `segmentPersonnel[]`，**表 13 续** `STRTIME`、`ENDTIME`、`DISTANCE`（km）、`DURATION`（min）、`START_LGTD`/`START_LTTD`、`END_LGTD`/`END_LTTD`（**LGTD=经度、LTTD=纬度**，°）；`segmentPatrolNo` 仍存库/对接，保存时按行自动生成（`PATROL-S序号`），**巡检记录表格不展示段巡河编号列**（河段编码仅在台账头展示）。**每条巡检记录与一条巡河轨迹一对一**（`trackSummary` / 轨迹 ID 由接口回写）。列表「巡河人员」为各段巡检人员去重合并。
  - **DYN_WATER_QUALITY** 水质监测记录表：`SECTION_ID`、`DETECTION_DATE`、`ADDVCD`、`HC_TYPE`、`QUALITY`（水质类别 1–6 类）等
  - **FOU_USER** 河湖长信息表：`USER_ID`、`NAME`、`MOBILE`、`USER_TYPE`、`ADDVCD` 等；原型中对应 **河长通讯录** 类型 `RiverChiefContactRow`（见 `initialRiverChiefContacts`）
  - **事务列表（上报事件语义）**：`RiverGuardAffairRow` **无** `affairType`；表单侧问题类型以 **`RIVER_GUARD_AFFAIR_EVENT_PROBLEM_TYPES`** 为主（「其他」可填自定义），台账 `problemType` 存最终字符串；历史数据可仍为旧版 **`RIVER_GUARD_PROBLEM_TYPES`** 值。另含问题描述、现场照片与视频、处理措施与过程、结果、反馈意见等；台账可含历史 `initiateTime`/`initiateSubject`；嵌套 **事务处置** `disposal`（含 **处置负责人** `disposalLeader`、联络电话、完成时间、现场图等；台账仍可保留历史字段如 `disposalProgress`、`disposalDescribe`，编辑表单不展示）。交互对齐应急协同类页面（列表 + 增删改查 + 字段管理 + 处置 Tab）；**严重程度、责任主体、责任人**紧接信息来源之后；**详情**同 Tab `Descriptions` 字段顺序与编辑对齐；**处理状态**等在「事务处置」
- **关键字段（项目管理 · 项目信息台账）**：
  - 基础信息：项目名称、项目编号、项目类型、建设地点
  - 规划工期：计划开始日期、计划结束日期（`startDate` / `endDate`）
  - 投资与进展：投资金额（万元）、项目状态、完成进度（%）
  - 参建与责任：责任单位、施工单位、监理单位（`supervisor`）
  - 目标与说明：项目目标（`projectGoal`，管理决策与考核依据）、项目描述/建设内容（`description`）
