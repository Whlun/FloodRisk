# 服务常驻运行说明（macOS + launchd + Nginx Proxy Manager）

本文用于保证 `AxhubMake` 在关闭 Cursor、关闭终端或关闭 AI 会话后仍持续运行。

## 1. 适用环境

- 操作系统：macOS
- 进程守护：`launchd`（系统自带）
- 反向代理：Nginx Proxy Manager（NPM）
- 项目路径：`/Volumes/WhlunService/AxhubMake`
- 服务端口：`51730`

## 2. 守护配置文件

配置文件路径：

- `~/Library/LaunchAgents/im.axhub.make.dev.plist`

建议内容如下：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
  <dict>
    <key>Label</key>
    <string>im.axhub.make.dev</string>

    <key>ProgramArguments</key>
    <array>
      <string>/bin/zsh</string>
      <string>-lc</string>
      <string>cd /Volumes/WhlunService/AxhubMake &amp;&amp; npm run start -- --host 0.0.0.0 --port 51730</string>
    </array>

    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>

    <key>WorkingDirectory</key>
    <string>/Volumes/WhlunService/AxhubMake</string>

    <key>StandardOutPath</key>
    <string>/tmp/axhub-make.out.log</string>
    <key>StandardErrorPath</key>
    <string>/tmp/axhub-make.err.log</string>
  </dict>
</plist>
```

## 3. 启动与管理命令

### 3.1 首次加载（或修改配置后重载）

```bash
launchctl unload ~/Library/LaunchAgents/im.axhub.make.dev.plist 2>/dev/null
launchctl load ~/Library/LaunchAgents/im.axhub.make.dev.plist
launchctl start im.axhub.make.dev
```

### 3.2 运行状态检查

```bash
launchctl list | grep im.axhub.make.dev
lsof -nP -iTCP:51730 -sTCP:LISTEN
```

### 3.3 健康检查

```bash
curl -I http://127.0.0.1:51730
```

### 3.4 重启服务

```bash
launchctl kickstart -k gui/$(id -u)/im.axhub.make.dev
```

### 3.5 停止服务

```bash
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/im.axhub.make.dev.plist
```

### 3.6 重新启动已停止服务

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/im.axhub.make.dev.plist
```

## 4. 日志排查

查看标准输出日志：

```bash
tail -f /tmp/axhub-make.out.log
```

查看错误日志：

```bash
tail -f /tmp/axhub-make.err.log
```

常见现象：

- 端口未监听：通常是启动命令异常退出，先看 `err.log`
- 任务存在但无法访问：检查是否监听在 `0.0.0.0:51730`
- NPM 返回 502/504：先确认本机 `51730` 可访问，再检查反代配置

## 5. 公网访问登录保护

当 `51730` 通过 NPM 或其它方式暴露到公网时，建议在 `.axhub/make/axhub.config.json` 中开启登录保护：

```json
"server": {
  "auth": {
    "enabled": true,
    "username": "admin",
    "password": "请改为强密码",
    "allowLocalBypass": true,
    "sessionMaxAgeSeconds": 3600
  }
}
```

`sessionMaxAgeSeconds` 可省略，省略时**默认 3600 秒（1 小时）**；登录后超过该时间需重新登录。示例中的 `3600` 与默认值相同，写上仅为便于按需改成其它秒数。

说明：

- **仅通过域名**（如 NPM 反代后的 `https://你的域名`）访问时，会进入登录页（`/login`），输入账号密码后使用；登录态默认 **1 小时** 有效。
- 浏览器地址栏为 **`localhost` / `127.0.0.1` / `192.168.x.x`（及 10.x、172.16–31 私网 IP）** 时**不需要登录**，可直接打开管理台（`allowLocalBypass` 默认开启，且需 `allowLAN: true`）。
- 登录后若右侧预览区出现**第二个管理台侧栏**（套娃），请 **强制刷新整页**（`Cmd+Shift+R`）；已禁止管理台首页在 iframe 内嵌套，刷新后左侧选中原型即可正常预览。
- 修改配置后需**重启** `npm run start` 才会生效。
- 密码保存在本机 `.axhub/make/axhub.config.json`（已在 `.gitignore` 中，不会提交到 Git）。

默认示例账号（请尽快修改密码）：

| 项 | 值 |
| --- | --- |
| 用户名 | `admin` |
| 密码 | `Axhub@2026` |

退出登录（任选其一）：

- **管理台**（`http://…:51730/` 左侧「产品原型」树）：文件树**下方空白区** **「退出登录」**（与侧栏同宽）
- **一张图原型**（湖州 / 韶山等）：顶栏右侧 **「管理员 ▾」** → 点击展开 → **退出登录**
- 访问 `/logout` 或 `/__axhub/auth/logout`
- 打开 `/login`，若已登录可点 **「退出登录」**

## 6. Nginx Proxy Manager 对接检查

在 NPM 中确认以下配置：

- `Forward Hostname / IP` 指向运行本服务的主机
- `Forward Port` 为 `51730`
- 协议使用 `http`
- 开启 WebSocket Support（如需实时能力）

建议检查顺序：

1. 本机访问 `http://127.0.0.1:51730` 是否正常
2. 局域网访问 `http://<服务机器IP>:51730` 是否正常
3. 最后再验证域名访问

### 管理台一直显示「正在加载管理台…」

首屏需加载较大的管理台脚本（`vendor-common.js` 等，gzip 后约 2MB）。局域网 Chrome 首次打开可能需 **30–90 秒**，页面会显示已等待秒数。

若超过 2 分钟仍无界面：

1. 先试本机：`http://127.0.0.1:51730/`（排除局域网/Wi‑Fi 问题）
2. 打开开发者工具 → **Network**，看 `vendor-common.js`、`index.js` 是否失败或长期 pending
3. **硬刷新**（Cmd+Shift+R）或清除该站点缓存后重试
4. 健康检查页：`http://<服务机器IP>:51730/health`（纯 HTML，不依赖大脚本）

## 7. 验收标准

满足以下条件即视为“关闭 AI 会话后服务仍正常”：

- 关闭 Cursor 或 AI 对话后，`51730` 端口仍持续监听
- 手动杀掉服务进程后，`launchd` 能自动拉起新进程
- 通过 NPM 代理域名访问页面正常
